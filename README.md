# Тарози API

Бэкенд системы учёта для магазина: товары и склад, касса, клиенты и долги, маркетинг, отчёты, сотрудники.
Python 3.12+, FastAPI, SQLAlchemy 2, PostgreSQL (для разработки подходит SQLite).

## Запуск

**Быстро, без базы данных (SQLite):**

```bash
pip install -r requirements-dev.txt
python seed.py                       # демо-данные: логин demo, пароль demo12345
uvicorn app.main:app --reload
```

Документация со всеми запросами и кнопкой «Try it out»: http://localhost:8000/docs

**С PostgreSQL через Docker:**

```bash
SECRET_KEY=длинная-случайная-строка docker compose up --build
docker compose exec api python seed.py   # по желанию
```

**Тесты:** `pytest`

## Как устроено

| Раздел | Адреса | Что делает |
|---|---|---|
| Вход | `/api/auth/register`, `/login`, `/me` | Регистрация бизнеса (компания, первый магазин, владелец, роли Кассир / Старший продавец / Менеджер), вход по логину и паролю, JWT-токен |
| Настройки | `/api/company`, `/api/stores`, `/api/targets` | Валюта, % бонусов, порог малого остатка, продажа в минус, часовой пояс; магазины; цели по выручке |
| Сотрудники | `/api/users`, `/api/roles`, `/api/permissions` | Сотрудники с доступом к выбранным магазинам; роли из 12 прав |
| Товары | `/api/products`, `/categories`, `/suppliers`, `/products/import`, `/products/barcode/{код}` | Каталог с вкладками «Активные / Неактивные / Малый остаток / Нулевой остаток», поиск, сканер, импорт CSV, журнал движений товара |
| Склад | `/api/stock/{вид}` | Документы `supplier_order` (приход), `inventory`, `transfer`, `writeoff`, `repricing`. Создаётся черновик, остатки меняются по `…/complete` |
| Касса | `/api/sales/quote`, `/api/sales`, `/held`, `/{id}/complete`, `/{id}/returns` | Пересчёт чека, продажа (наличные, карта, в долг, бонусы, смешанная оплата), отложенные чеки, частичные возвраты |
| Клиенты | `/api/clients`, `/client-groups`, `/clients/{id}/debt-payments` | База, группы со скидкой, теги, бонусы, долги и их погашение, история покупок |
| Маркетинг | `/api/marketing/promotions`, `/promo-codes`, `/sms` | Акции на товары и категории, промокоды (% или сумма, лимит, срок), SMS-рассылки |
| Отчёты | `/api/reports/dashboard`, `/stores`, `/products`, `/sellers`, `/clients`, `/marketing` | Главная (выручка, платежи, график по дням, топы, цель) и отчёты с прибылью и маржой |

Правила, которые стоит знать:

- **Остаток** меняется только через `services/stock.py`, и каждое изменение пишется в журнал `stock_movements`.
- **Скидка на строку**: берётся бо́льшая из скидки группы клиента и действующей акции. Промокод применяется ко всему чеку и раскладывается по строкам, чтобы при возврате вернуть точную сумму.
- **Оплата**: сумма оплат плюс бонусы должна точно равняться сумме чека (сдачу считает касса). Продажа в долг и бонусы требуют выбрать клиента.
- **Бонусы** начисляются только с наличных и карты. При возврате начисленные бонусы списываются пропорционально.
- **Розничная цена** меняется только переоценкой, чтобы осталась история. Своя цена на кассе доступна только с правом `products.write`.
- **Данные компаний** изолированы: каждый запрос видит только записи своей компании, а сотрудник — только свои магазины.

## Перед запуском в работу

1. Задайте `SECRET_KEY` и `DATABASE_URL` в `.env` (образец: `.env.example`).
2. Таблицы сейчас создаются автоматически при старте. Чтобы менять структуру базы без потери данных, подключите миграции Alembic: `alembic init`, затем `target_metadata = Base.metadata`.
3. SMS пока только пишутся в лог: подключите провайдера в `app/services/sms.py`.
4. Отчёты считаются в Python по продажам за период. Для сотен тысяч чеков в месяц их стоит перевести на SQL-агрегаты.
5. Не сделано: обмен товара (пока это возврат плюс новая продажа), печать чеков и фискализация, открытие и закрытие смены с кассовыми остатками, загрузка фото товаров.
